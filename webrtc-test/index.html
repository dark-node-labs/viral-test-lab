What does a WebRTC test check?

This WebRTC test checks browser access to camera and microphone input, screen sharing, media device enumeration, and local preview playback. It is useful before Zoom, Google Meet, Microsoft Teams, browser recording, online classes, and live streaming.

Why does WebRTC need permission?

Browsers require explicit permission before a website can read camera, microphone, or screen content. Permission is requested only after you press a test button. If access fails, review browser site settings and operating system privacy controls.

Does this WebRTC test upload video or audio?

No. The camera, microphone, and screen-share checks are local browser previews. This page does not create a call server or upload media for the check.

WebRTC troubleshooting

If a device is missing, reconnect it and scan again. If a permission prompt does not appear, open the site settings near the browser address bar and allow the relevant device. Close other meeting or recording apps that may already be using the camera or microphone.

Project reference

The media checks follow the browser capabilities demonstrated by the WebRTC Samples project, which is licensed under BSD-3-Clause. Quick Test Hub presents an original, focused interface around the standard browser APIs.

WebRTC Test FAQ

Can I test screen sharing without joining a call?

Yes. Start Screen Share and choose a tab, window, or screen. The selected stream appears locally until you stop it.

Why are device names hidden?

Browsers often hide device labels until the page has permission to use a camera or microphone. The device count can still be available before labels are revealed.
